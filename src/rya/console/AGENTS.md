# `rya.console` - the built console asset

This package ships **only build output**. The console's source is
[`web/console/`](../../../web/console/) (Vite + React + TypeScript); this directory
exists so the compiled bundle can travel inside the wheel.

```
__init__.py   marker
dist/         build output of web/console/ - gitignored, force-included into the wheel
```

`rya serve` serves `dist/index.html` at **`/`** and mounts `dist/assets/` at
`/assets`. `/v2`, the address the React console held during the migration,
308-redirects to `/`.

> **Never edit `dist/` by hand.** It is regenerated by
> `scripts/build_console.sh` (which runs the frontend tests, typechecks and
> builds). Edit `web/console/src/` instead.

## What used to be here, and why it is gone

Until the migration completed, `/` was served by `index.html` in this directory: a
single 127KB file with the entire SPA inline, plus a self-hosted `lucide.min.js`
(~400KB of vendored icons) to keep the CSP free of a third-party script origin.
Both are deleted. Every one of its 23 views now has a React component, so keeping
a second console would have meant maintaining two that drift - and the migration's
own rule was "delete nothing from `/` until parity is reached", which is now
satisfied rather than waived.

Three things improved by the removal rather than merely changing:

- **The CSP dropped `script-src 'unsafe-inline'`.** A console whose application is
  one inline `<script>` cannot have that; a bundle of external modules can. The
  allowance is gone from the policy, not just unused.
- **~530KB of committed vendored JavaScript left the repo and the wheel.** Icons
  are `lucide-react` imports now, tree-shaken into the bundle.
- **The console is typechecked and unit-tested.** The legacy file had no build step
  and therefore no test harness; `web/console` has vitest and `tsc --noEmit`.

## Packaging contract

**Node is a release-time dependency, never an install-time one.** `pip install
rya-server` needs only Python, because `dist/` is already in the wheel.

- `dist/` is gitignored. The root `pyproject.toml` opts it past the VCS-ignore with
  `artifacts = ["src/rya/console/dist/**"]` (the Airflow pattern).
- **An absent `dist/` is an ordinary state**, not an error: a fresh clone that never
  ran `npm install` has no bundle. `GET /` then returns a **503 naming the build
  command**, and the API is unaffected. It must never be a 404 and must never be an
  import-time crash - `_console_dist_dir()` and `_console_index()` in
  `api/app.py` both degrade to `None`.
- The asset mount is deliberately narrow (`/assets`, not `/`). A `StaticFiles`
  mount at `"/"` is a route that matches every path, and Starlette matches in
  registration order, so it would shadow every API route declared after it. Serving
  `index.html` from an explicit route keeps that hazard out of the design instead of
  depending on where the block sits in `build_app`.

## Where the design notes went

The reasoning that used to live here - the `workspace → agent → environment →
version → runs` drill-down, why Workers asks for every status, why the quotas page

[`web/console/AGENTS.md`](../../../web/console/AGENTS.md). Read that before changing
